The five layers, explained

Same architecture everywhere, and the order is the stack: rules → know-how → access → packaging → parallelism. Each layer only earns its place when the one before it isn't enough.

Terminology traps

  • "Plugin" is the most overloaded word in the ecosystem. In Claude and Codex, a plugin is a distribution bundle (skills + MCP + commands). In Hermes, OpenClaw, and OpenCode, a plugin is a code extension — a Python or JS file that adds tools and hooks to the runtime. Osaurus splits the difference: its plugin is a native code extension packaged as a bundle (binary + SKILL.md + UI in one zip). Same word, three different meanings.
  • "Extension" flips meaning too. In Goose, an extension is an MCP server (tool access). In Gemini CLI, an extension is a bundle. In Zed it's an editor bundle — themes, languages, language servers, debuggers — which can carry an MCP server but has no manifest field for a skill or an instruction file, so it stops short of being an agent bundle. Copilot used the word for its marketplace GitHub Apps until they were sunset in Nov 2025 — so older Copilot writing means something that no longer exists. Check which layer, and which year, before assuming.
  • "Skills" is the safest word. Everyone who implements it means the same SKILL.md open standard, and every harness here supports it bar one — Jan has no skills layer at all. The wrinkles are in distribution and authorship, not format: Hermes skills can be written by the agent itself, and OpenClaw ships them as versioned ClawHub bundles. Note also that the shared folder is increasingly the vendor-neutral .agents/skills rather than any one vendor's directory.
  • "Connector" is mostly Claude-speak for a packaged remote MCP server — though the word shows up generically elsewhere to mean any MCP integration.

The layer underneath: MCP

The Model Context Protocol (open standard, released by Anthropic in Nov 2024) is the shared plumbing for the "tool access" row — a JSON-RPC protocol where a server publishes tools any compatible agent can discover and call. This is why the ecosystem interoperates: a Goose extension, a Claude connector, a Hermes MCP entry, and an MCP server inside a Codex plugin can be the exact same server. Osaurus demonstrates the two-way nature of the standard: it consumes remote MCP servers and exposes its own local tools as an MCP server that other harnesses can connect to — so your Osaurus toolbox can serve Claude Desktop. Skills (SKILL.md / agentskills.io) and instruction files (AGENTS.md) are similarly portable open standards. The names are vendor branding; the files and protocols underneath increasingly are not.

Portability

You've set one harness up; what survives if you add or switch to another? Three things travel as open standards — AGENTS.md instructions, SKILL.md skills, and MCP servers — and several tools read each other's directories outright, so one folder can serve many.
